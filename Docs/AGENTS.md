# Documentation rules

## Style

- Use concise technical English.
- Describe behavior rather than implementation details unless explicitly relevant.
- Use the same terminology as the source code.
- Do not use marketing language.

## API documentation

Every public class and method should document:
- purpose
- parameters
- return value
- exceptions/errors
- important ownership/lifetime behavior
- relevant performance characteristics

## Examples

- Examples must compile.
- Prefer examples from existing tests.
- Do not invent APIs.
